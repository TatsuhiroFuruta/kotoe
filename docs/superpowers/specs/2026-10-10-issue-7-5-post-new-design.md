## 決めたこと

### 決定 1：送信は `fetch`（`apiFetch`）のまま。進み具合（%）は出さない

送信中はボタンを押せなくし、「投稿中…」と出す。デザインブリーフは「アップロード中（プログレス）」を
求めているが、進み具合の分からない表示で代える。

- `fetch` は送信の進み具合を取れない。% を出すには `XMLHttpRequest`（`xhr.upload.onprogress` が
  `loaded` / `total` を持つイベントを送信中に発火する）が要る
- XHR 版を `api.ts` に足すと、401 時のトークン破棄・timeout・`ApiError` への変換を 2 か所に持つことになり、
  片方だけ直して食い違う危険がある
- 5MB の送信は、上り 50Mbps で約 1 秒、10Mbps（4G）で約 4 秒。% が無くて困るのは弱い電波（1Mbps で約 40 秒）に限られる
- **% が表すのはブラウザ → Rails の区間だけ**。Rails → Cloudinary（最大 60 秒）は表れないので、100% のあとにも
  待ちが残る。XHR にしても「100% のあとは『保存中…』」のような別の表示が要る
- `fetch` で送信の進み具合を取る方法（本文に `ReadableStream`）は Chromium 系だけで、HTTP/2 も要る。現時点では使えない

必要になったら、`api.ts` に XHR の送信関数を 1 つ足して切り替える（呼び出し側の差分は小さい）。

### 決定 2：画像のサイズと形式は、選んだ時点でフロントでも確認する

`lib/posts/image-file-check.ts` の純粋関数 `checkImageFile(file)` が、エラーコードか null を返す。

- **正はバック（`Images::Validation`）。フロントの値は早く知らせるための写し**。ずれてもバックが最終的に弾くので、
  安全側に倒れる。コードのコメントにもそう書き、`MAX_BYTES` と形式の一覧の出どころを示す
- **返すのはバックと同じエラーコード**（`image_too_large` / `image_type_not_allowed`）。翻訳の辞書が 1 つで済む
- 理由：バックは本文を受け取り終えてから判定するので、15MB の写真を 1Mbps で送ると、約 2 分待ったあとに
  弾かれる（実際にはその前に timeout する）。スマートフォンの写真は 8〜15MB になることがある
- **`file.type` が空なら形式の判定をしない**（バックに任せる）。HEIC は Chrome・Firefox で空になりやすく、
  弾くと正しい HEIC を拒否してしまう。`file.type` は拡張子由来で、バックのマジックバイト判定とは一致しない
- サイズの境界はバックと同じ「超えたら」（5MB ちょうどは通す）
- `<input accept>` は `image/jpeg,image/png,image/webp,image/heic,image/heif` にする。ファイル選択画面の絞り込みで、
  判定ではない（ドラッグ＆ドロップは `accept` を通らないので、確認は `checkImageFile` が担う）

### 決定 3：timeout は 120 秒

| 区間 | 最悪の場合 |
|---|---|
| ブラウザ → Rails（5MB を 1Mbps で送る） | 約 40 秒 |
| Rails → Cloudinary（gem の既定 timeout） | 60 秒 |
| 合計 | 約 100 秒 → 余裕を見て **120 秒** |

既定の 15 秒は「Render のコールドスタートで必ず失敗させ、待つか抜けるかを選ばせる」ための値（7-2.7 決定 1）。
投稿画面は `RequireAuth` が `/api/me` の取得に成功してから出るので、**送信の時点でサーバーは起きている**。
長くしても「1 分間何も起きない」状態は生まれない。

### 決定 4：timeout したら「投稿されている場合がある」と知らせ、一覧へのリンクを置く

Rails が本文を受け取ったあとに timeout すると、お題はサーバー側で作られている可能性がある。一般的な
timeout の文言（`TIMEOUT_MESSAGE`：「少し待ってから再度お試しください」）では押し直しを促し、二重投稿になる。

- フォーム上部に「投稿に時間がかかっています。投稿が完了している場合がありますので、お題一覧で確認してから
  再度お試しください」と出し、`/posts` へのリンクを付ける（既定の新着順なので先頭に出る）。
  **リンクは新しいタブで開く**。同じタブで移ると、この画面の入力が消える
- 入力（画像・タイトル）はそのまま残す。投稿されていなければそのまま押し直せる
- 冪等キーは採らない。API とマイグレーションの変更になり、1 PR 1 issue を超える。120 秒を超えるのはまれで、
  二重になっても 7-6 のマイページで本人が削除できる

### 決定 5：「お題を投稿」はヘッダーの右側に、ログイン状態によらず出す

- 未ログインで押すと `RequireAuth` が `/login?next=/posts/new` へ送り、ログイン後に戻る。投稿できるサービスで
  あることが未ログインの人にも分かる
- デザインブリーフ 0 は「右に目立つ『お題を投稿』ボタン」。ボタンの見た目（`buttonClasses({ size: "sm" })`）で
  アカウント側のナビに置く
- `unreachable` でも出す。押した先の `RequireAuth` が再試行の画面を出すので、行き止まりにはならない
- `loading` の間は出さない（スケルトンの幅が状態で変わらないようにするため。他の項目と同じ扱い）
- 375px 幅では、未ログイン時の右側が 3 項目になり 2 行に折り返す可能性がある。ヘッダーは折り返す作り
  （7-3a）なので横にはみ出さない。ハンバーガーメニューは入れず、手動確認 6 で実際の見え方を見て判断する

### 決定 6：成功したらトーストを出し、お題詳細へ `replace` で移る

- トーストは「お題を投稿しました」（7-2.5 設計書で予約済み）
- `router.replace(postDetailHref(post.id))`。`push` だと、戻るボタンで空の投稿フォームに戻り「投稿が消えた」
  ように見える
- **送信中に別のページへ移っていたら、成功してもお題詳細へは移らない**（トーストだけ出す）。
  投稿画面以外の場所から勝手に連れ戻さないため
- お題詳細は応答の `post` を使わずに取り直す（`PostDetail` は id から取得する作り）。往復が 1 回増えるが、
  詳細側に初期値を渡す口を作るほどではない

### 決定 7：プレビューは object URL、HEIC は代替表示

- `URL.createObjectURL(file)` で表示し、選び直したときと画面を離れるときに `revokeObjectURL` で解放する。
  URL は**プレビュー用の子コンポーネントの effect で作って `<img>` に直接入れ**、effect の後片づけで解放する
  （state に入れると `set-state-in-effect` に当たる。`useMemo` で作ると、開発時の StrictMode の模擬的な
  再マウントで解放だけが走り、プレビューが壊れる）
- Safari 以外は HEIC を `<img>` で描けない。`onError` を受けたら「この形式はプレビューできません（投稿はできます）」と
  ファイル名を出す（壊れた画像のアイコンを出さない）
- 枠は画像そのものの縦横比にする（`h-auto w-auto max-h-80 max-w-full`。`PostHero` と同じ）。固定の枠に
  `object-contain` で収めると、縦長・正方形の写真で左右に帯が出る（2026-10-10 に計画の段階で修正）
- `src` に入るのは `createObjectURL` が返す `blob:` URL だけで、ユーザー入力の文字列は入らない（XSS の節）

### 決定 8：新しく作る純粋関数

| 関数 | 置き場所 | 役割 |
|---|---|---|
| `checkImageFile(file)` | `lib/posts/image-file-check.ts` | サイズ・形式の確認。エラーコードか null |
| `toPostFormErrors(error)` | `lib/posts/post-messages.ts` | 送信の失敗を `{ image?, title?, form? }` の日本語に振り分ける |
| `postFieldMessage(code)` など辞書 | `lib/posts/post-messages.ts` | エラーコード → 日本語 |

どちらも Vitest で確かめる（CLAUDE.md のテスト方針）。

## エラーの出し分け

置き場所は 7-2・7-3c にそろえる。**欄のエラーはその欄の直下**（`aria-invalid`・`aria-describedby`、最初にエラーが
出た欄へフォーカスを移す）、**欄に紐づかないエラーはフォーム上部**（`role="alert"`）、**失効はトースト**。

### 送る前（フロントの判定）

| 条件 | 出す場所 | 文言 |
|---|---|---|
| 画像を選んでいない | 画像欄（送信時） | 画像を選んでください |
| 5MB を超えている | 画像欄（選んだ時点） | 画像は 5MB 以下にしてください |
| 形式が違う（`file.type` が空なら判定しない） | 画像欄（選んだ時点） | JPEG・PNG・WebP・HEIC の画像を選んでください |
| タイトルが空、または空白だけ | タイトル欄（送信時） | タイトルを入力してください |

- 空白だけを空として扱うのは、Rails の `presence`（`blank?`）が空白だけの文字列を空と判定するため。
  全角スペース（U+3000）も両方で空白として扱われる（JS の `trim()` と Ruby の `[[:space:]]`）
- サイズ・形式で弾いたファイルは選んだ状態にしない（プレビューも出さない）。送れないものを送れるように見せない。
  **前に選んでいた画像も外す**（プレビューの下にエラーが出ると、どちらの画像のことか分からなくなる）
- フォームは `noValidate`。`TextField` は `required` を付けるので、そのままだとブラウザ標準の吹き出しが出て、
  画像とタイトルのエラーを同時に出せない

### 送ったあと（バックの判定）

| 応答 | 出す場所 | 内容 |
|---|---|---|
| 422 `image: [code]` / `title: [code]` | 該当する欄 | 上と同じ辞書（`image_missing` は「画像を選んでください」、`blank` は「タイトルを入力してください」） |
| 422 の未知のコード | 該当する欄 | 欄ごとの汎用の文言（例：「この画像は使えません」） |
| 422 の画面に無い欄 | フォーム上部 | 汎用の文言。**何も表示されない状態を作らない**（7-2 の辞書と同じ方針） |
| 502 `image_upload_failed` | フォーム上部 | 画像の保存に失敗しました。時間をおいて再度お試しください |
| 401 | トースト | `SESSION_EXPIRED_MESSAGE`。その後 `RequireAuth` がログイン画面へ送る |
| timeout | フォーム上部 | 決定 4 の文言＋`/posts` へのリンク |
| 通信断・その他の 2xx 以外 | フォーム上部 | `toRequestErrorMessage()` |

入力を直したら（画像を選び直す・タイトルを入力する）、その欄のエラーと `aria-invalid` を消す（7-3c と同じ）。
フォーム上部のエラーは次の送信で消す。

## 状態

`PostForm` が持つ。reducer には切り出さない（7-3c 決定 7 と同じ。遷移が少ない）。

| 状態 | 中身 |
|---|---|
| `selection` | 確認を通った `{ file, id }` か null。`id` は選び直すたびに増え、プレビューの `key` になる |
| `title` | 入力中の文字列 |
| `submitting` | 送信中か。true の間は送信ボタンと画像の選び直しを止める |
| `fieldErrors` | `{ image: string \| null; title: string \| null }` |
| `formError` | フォーム上部の文言（timeout のときはリンク付きの表示に切り替える）か null |

送信中に画像を選び直せないようにするのは、送った画像と画面のプレビューが食い違わないようにするため。
タイトルは送信中も入力できてよいが、送るのは押した時点の値。

### ドラッグ＆ドロップ

- `dragover` で `preventDefault()`（しないとブラウザがファイルを開いて画面を離れる）、`drop` で `dataTransfer.files[0]`
- 複数ファイルを落とされたら先頭の 1 枚だけを使う
- ドラッグ中は枠の色を変える（`border-accent`）。キーボード・スクリーンリーダーでは通常の「画像を選ぶ」で足りる
- 送信中は受け付けない

## 画面

中央にカード型のフォーム（デザインブリーフ 5）。上から：

1. 見出し「お題を投稿」
2. フォーム上部のエラー（あるとき）
3. 画像欄：未選択なら「画像を選ぶ／ここにドロップ」と形式・上限の案内（「JPEG・PNG・WebP・HEIC、5MB まで」）。
   選択後はプレビューと「選び直す」
4. タイトル欄（既存の `TextField`）
5. 「投稿する」ボタン（送信中は「投稿中…」で押せない）

色はデザイントークンだけを使う（`dark:` と生のパレットを書かない。7-2 の規約）。

## XSS

- タイトルは `{value}` で描く。`value` 属性への受け渡しも React がエスケープする
- `<img src>` に入るのは `URL.createObjectURL` の `blob:` URL だけ。ユーザーが書ける文字列は入らないので、
  `safeNextPath()` のような検証は要らない
- ファイル名（代替表示）は `{file.name}` で描く。ファイル名は利用者が自由に付けられるので、属性や URL には入れない

## 手動確認（ローカル）

1. **`RequireAuth` の確認 3 点**（backlog 7-5）
   1. ログイン中に `/posts/new` を直接ロード／リロードしても `/login` に飛ばされない
   2. 未ログインで開くと `/login?next=%2Fposts%2Fnew` へ行き、ログイン後に戻る
   3. backend を止めてリロードすると、`/login` へ飛ばされず「サーバーの応答がありません」＋再試行が出る。
      backend を戻して再試行するとフォームが出る
2. 投稿に成功し、お題詳細へ移ってトーストが出る。戻るボタンで投稿フォームに戻らない。お題一覧の先頭に出る
3. **縦横比の違う画像**（16:9・3:4・正方形）のプレビューと、投稿後のお題詳細・一覧での表示
4. 5MB を超える画像、許可しない形式（GIF・PDF）、HEIC（Chrome での代替表示と、投稿できること）、ドラッグ＆ドロップ、
   複数ファイルのドロップ
5. 未入力で送ったときのエラー表示とフォーカスの移動。入力を直すとエラーが消える
6. ヘッダーの 375px 幅：未ログイン・ログイン中・`unreachable` の 3 状態で、横にはみ出さないこと
7. キーボードだけで画像を選んで投稿できる

502 と timeout は手元で起こしにくいので、振り分けを Vitest で確かめるところまでにする。

## 既知の制約

- **投稿中に 401 が返ると入力が消える。** `api.ts` がトークンを捨て、`RequireAuth` がログイン画面へ送るので、
