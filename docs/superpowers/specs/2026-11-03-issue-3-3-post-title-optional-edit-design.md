- 依存：3-2（お題の CRUD）、6-3（マイページ API と `PostSummarySerializer`）、7-5（投稿フォーム）、7-6a / 7-6b（マイページの表示と操作、確認ダイアログ）
- 作成日：2026-11-03

- 前提：CLAUDE.md「XSS」「テスト戦略」「メッセージ・エラー・i18n の責務」

## なぜ今やるか

ユーザーの判断（2026-11-03）。3-3 は背骨の外にあったが、MVP 公開の前に入れる。

- **上限は、データが溜まってから付けると整合が崩れる。** 上限を超えたお題が既にあると、「触っていないタイトルが
  長すぎて編集を保存できない」状態が生まれる。公開前なら違反データが無いので、バリデーションを足すだけで済む
- **任意化は、タイトルを表示する画面が増える前にやる。** 今は 7 コンポーネント程度。7-7（ランキング・トップ）の前に済ませる

## この issue で作るもの

1. タイトルを**任意**にする（空なら NULL で保存し、画面では「無題」と出す）
2. タイトルの**上限 30 字**（投稿・編集の両方）
3. `PATCH /api/posts/:id`（自分のお題の**タイトルだけ**を変える）
4. マイページ「投稿したお題」のカードの下に「タイトルを編集」ボタン → 入力ダイアログ
5. `title: null` を「削除済み」の合図にしているフロントの判定を、`discarded` フラグに一本化する
6. backlog への積み残し：描写文を検索の対象にする issue（決定 6）

完了条件（backlog を更新したもの）：タイトル無しでお題を投稿でき、一覧・詳細・マイページで「無題」と表示される。
30 字を超えるタイトルは投稿・編集とも 422 と `too_long` で弾かれる。自分のお題のタイトルをマイページから変更・消去でき、
画像と既存の挑戦は影響を受けない。

**この issue で作らないもの**

| 項目 | 理由・担当 |

| 画像の差し替え | backlog 3-3 のとおり。挑戦者は「その画像」を描写しているため |
| お題の削除 UI | API（3-2）はあるが画面は別 issue。今回のボタン行に並べたくなっても足さない |
| お題詳細からの編集 | 決定 4。入口はマイページだけ |
| 描写文を検索の対象にする | 決定 6。backlog に積むだけ |

## 決めたこと

### 決定 1：タイトルは任意。空は NULL で保存する

ユーザーの決定（2026-11-03）。画像だけで投稿したい人がいるため。検索のためにタイトルの欄そのものは残す。

- マイグレーションで `change_column_null :posts, :title, true`。既存行はすべて値があるので影響なし
  （`down` は NULL の行があると失敗する。戻すときは先に埋める必要があることをマイグレーションのコメントに書く）
- `presence` のバリデーションを外す
- **空欄・空白だけの入力は NULL にそろえる**（私の判断）。`normalizes :title, with: ->(title) { title.presence }`。
  Rails の `blank?` は全角スペースも空白として扱う。空文字と NULL が混ざると、将来の検索や「無題」の判定が二通りになるため。
  前後の空白を削る（strip）ことはしない（今の挙動を変えないため）
- 投稿フォームの送信前チェック（`isBlankTitle` で弾く処理）は外す。ラベルは「タイトル（任意）」

### 決定 2：上限は 30 字

ユーザーの決定（2026-11-03）。**タイトルは「お題の名前」として扱い、説明は挑戦者に任せる。** 長いタイトルを許すと、
そのまま描写文に写すだけで再現度が出てしまい、Kotoe の遊び（自分の言葉で描写する）が弱まる。
30 字ならどの画面幅でもカードの 2 行に収まる。

- `validates :title, length: { maximum: 30 }, allow_nil: true`。上限は定数（例：`Post::MAX_TITLE_LENGTH`）にする
- **DB の型は変えない**（モデルのバリデーションだけ）。上限を変えたくなってもマイグレーションが要らない
- エラーコードは Rails 既定の `too_long`。投稿（POST）と編集（PATCH）で同じコードを返す
- **数え方は描写文の前例に合わせる**（私の判断）：判定は Rails の `length`（コードポイント）。フロントのカウンタは
  `text.length` で表示だけ行い、判定は 422 に任せる。絵文字ではフロントが多めに数えるが、「超えていないと表示したのに 422」にはならない
- フロントは `maxLength` で入力を止めない（前例どおり。超えたら赤字のカウンタと 422 の文言で知らせる）
- フロントの辞書（`post-messages.ts` の `TITLE_MESSAGES`）に `too_long` を足す。文言の案：「タイトルは 30 文字以内にしてください」。
  `blank` は投稿では返らなくなるが、辞書からは消さなくてよい（作り手に任せる）

### 決定 3：無題の見せ方は「無題」

ユーザーの決定（2026-11-03）。絵画や写真で題を付けない作品を「無題」と呼ぶ慣習に合い、「お題：無題」と自然に読める。

- 見出しの位置に**灰色（`text-ink-muted`）で「無題」**と出す。カードの高さが揃う
- 画像の alt / aria-label は「お題の画像」
- マイページは「お題：無題」
- 文言はフロントに 1 か所で持つ（例：`lib/posts/post-title.ts` に `UNTITLED_LABEL` と、見出し用の表示を返す関数）。
  置き場所と関数の形は作り手に任せる
- 対象：上の「タイトルの表示箇所」すべて。`<title>`（ページのメタデータ）は今も固定文字列なので変わらない

### 決定 4：編集はマイページのカード下のボタンから、ダイアログで

ユーザーの決定（2026-11-03）。

- 「投稿したお題」タブのカードの下に「タイトルを編集」ボタンを置く。**`PostCard` のリンクの外**に置く
  （7-6b 決定 3 と同じ理由：押せる要素の入れ子は HTML の規則違反）。`PostCard` 自体は一覧と共用なので変えない。
  マイページ側で `<PostCard>` とボタンの行を並べる
- 押すとダイアログが開く：見出し「タイトルを編集」、入力欄（今のタイトルが入った状態。無題なら空）、
  カウンタ「n / 30」、補足「空欄にすると「無題」になります」、ボタン「やめる」「保存する」
- 部品は 7-6b の `ConfirmDialog` と同じく `<dialog>`＋`showModal()`。`ConfirmDialog` には入力欄の口が無いので、
  外枠（開閉・Esc・送信中に閉じない処理）を共有する形に切り出すか、新しい部品にするかは作り手に任せる。
  **7-6b で実測した「Esc を 2 回押すと cancel を取り消せない」への対処（`onClose`）は落とさないこと**
- 開いたときは入力欄にフォーカス。閉じたら「タイトルを編集」ボタンへフォーカスを戻す
- **挑戦が付いたお題も編集できる**（backlog 3-3 の案A。ユーザーの決定）。名前を後から付ける・直す場面が自然にあるため
- **タイトルを消して無題に戻すこともできる**（決定 1 からの帰結）

**保存したあと**

- 成功：ダイアログを閉じ、トースト（success。案：「タイトルを変更しました」）、一覧を取り直す
  （その場で書き換えるか取り直すかは作り手に任せる。統計は変わらないので取り直さなくてよい）
- 変更が無いまま「保存する」：送ってよい（同じ値の PATCH は 200）。送らずに閉じるかは作り手に任せる
- 422 `too_long`：ダイアログを閉じずに、入力欄の下にエラーを出す
- 404（別のタブで削除した、など）：ダイアログを閉じ、一覧を取り直し、トースト（error。案：「このお題は削除されています」）
- 401：`api.ts` の失効処理に任せる（7-2.6）。ダイアログ用のトーストは重ねない
- 通信の失敗・5xx：ダイアログを閉じずにエラーを出し、もう一度押せるようにする。文言は `toRequestErrorMessage` に任せる
- 送信中は「保存する」を押せなくし、Esc でも閉じない（二重送信の防止。`ConfirmDialog` と同じ）

### 決定 5：`title: null` の二重の意味をなくす

私の判断。`AttemptPostSummary` では今後、`title: null` が「削除済み（伏せた）」と「無題」の両方を意味する。

- **バックエンドは変えない。** `discarded` が既にあり、それで区別できる
- フロントの判定をすべて `post.discarded` に寄せる。`title === null` を削除済みの合図として読む箇所を残さない
  - `myAttemptCardLabel`：`discarded` ならお題の部分を省き、そうでなければ「お題：<タイトルか「無題」>」
    （引数の型に `discarded` を足す）
  - `draft-card.tsx`：見出しは今どおり `discarded` で分岐し、そうでないときに「無題」を出す。alt / aria-label も同じ
  - `my-attempt-card.tsx`：同上
- `AttemptPostSummary` の型コメント（`types/api.ts:114`）を「削除済みなら title と image_public_id は null。
  削除済みでなくても、無題なら title は null」に直す

### 決定 6：検索は今回変えない。将来は描写文も対象にする

ユーザーの決定（2026-11-03）。無題のお題は今の検索（タイトル部分一致）にかからないが、それは受け入れる。

- 将来の方針：`?q=` で、タイトルに加えて**公開済み・未削除の挑戦の描写文**も部分一致で見る（`EXISTS` のサブクエリ）。
  挑戦者の描写はタイトルより情報が多いので、無題のお題も挑戦が付けば見つかる。追加の費用・外部 API は要らない。
  件数が増えたら日本語の部分一致に強い索引（pg_bigm / pg_trgm）を検討する
- 公開 API は `?q=` のままなので、そのときもフロントは変わらない（`Post.search_by_title` の中身を差し替える）
- **この issue では backlog に未着手の issue として積むだけ**（番号は 3-5 を想定。作り手が既存の番号と衝突しないか確かめる）
- この issue で守ること：無題は必ず NULL（決定 1）

## API

### `PATCH /api/posts/:id`

- 認証必須。対象は `current_user.posts.kept.find(params[:id])`（`destroy` と同じ形）。
  他人のお題・存在しない ID・削除済みはすべて 404 `not_found`
- 受け付けるのは `post[title]` だけ。`image` などほかのキーは **permit しない**（無視されるのではなく、受け取らない）
- `post[title]` が空文字・空白・`null` なら無題にする（決定 1）
- **`post` が無い、または `post` に `title` キーが無い**ときは何も変えずに 400 を返す（私の判断）。
  キーが無いだけで無題になると、壊れたクライアントがタイトルを消してしまうため。
  Rails の `ActionController::ParameterMissing` の既定の応答が JSON になるかは作り手が確かめ、
  ならなければ `{ error: "parameter_missing" }` に揃える
- `post` がハッシュでない（スカラー・配列）ときは、`title` キーが無いのと同じ扱いで 400 にする（500 にしない。
  `create` の `post_attributes` と同じ考え方。私の判断）
- 成功：200、`{ "post": PostSerializer の形 }`（`post_json` を使う）
- 検証エラー：422、`{ "errors": { "title": ["too_long"] } }`
- ルートは `resources :posts, only: %i[index create show update destroy]`

### `POST /api/posts`（変更）

- `title` が無い・空でも 201。保存される `title` は NULL
- 30 字を超えると 422 `{ errors: { title: ["too_long"] } }`（`collect_errors` が自動で拾う。画像はアップロードされない）

### 応答の型

- `PostSummary.title` を `string | null` にする（`types/api.ts:52`）。型を変えると表示箇所が型エラーで洗い出せる

## 手動確認（ブラウザ）

- タイトル無しで投稿 → お題詳細の見出しが灰色の「無題」→ 一覧のカードも「無題」、高さが他のカードと揃う
- 空白だけ（全角スペース）で投稿 → 同じく無題
- 31 字で投稿 → 422 の文言が欄の下に出る、画像は残ったまま直せる
- マイページ「投稿したお題」→「タイトルを編集」→ 今のタイトルが入っている → 変えて保存 → カードに反映、トースト
- 空にして保存 → 「無題」になる。もう一度開くと入力欄は空
- 31 字で保存 → ダイアログの中にエラー、閉じない
- 挑戦が付いたお題のタイトルを変える → お題詳細・挑戦詳細・「自分の挑戦」カードの「お題：…」が新しい名前になる
- 無題のお題への挑戦・下書きがマイページで「お題：無題」と出て、**「お題は削除されました」と出ない**
- 無題のお題に「無題」で検索してもかからない（意図どおり）
- キーボードだけで：ダイアログが開く・入力欄にフォーカス・Esc で閉じる・ボタンにフォーカスが戻る
- 別のタブでお題を削除してから編集 → ダイアログが閉じ、一覧から消え、トースト
- **直接ロード**（`/mypage?tab=posts` をアドレスバーから）でも確かめる（7-1 の教訓）
