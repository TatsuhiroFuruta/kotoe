PR になるため。

- **7-6a（この issue）**：ヘッダー＋統計、4 タブの表示、空状態、ヘッダーからの入口
- **7-6b**：下書きの 生成する／編集／削除、下書きの受け口、挑戦の削除メニューと確認ダイアログ

GitHub の issue は #27 の 1 つのまま。7-6a の PR は `Refs #27`、7-6b の PR が `Closes #27` にする
（7-6a でクローズすると未着手の 7-6b ごと閉じてしまう）。

backlog の書き換え：

- 背骨の `→（7-6）→` を `→（7-6a → 7-6b）→` に直し、まとめの箇条に分けた理由を 1 行足す

### 決定 2：下書きの再開はお題詳細で行う（7-6b への申し送り）

ユーザーの決定（2026-10-20）。7-6a では作らないが、7-6a の下書きカードの作りに関わるので記録する。

- 「生成する」「編集」は、どちらも `/posts/[id]?draft=<id>` に移り、描写フォームに下書きの文面を入れた
  状態で開く。生成はそこで「画像を生成」を押して行う
- 理由は 3 つ。描写フォーム（保存・生成・ポーリング・結果パネル）はお題詳細にしか無いこと。
  挑戦詳細は下書きを比較ビューにしない作りであること（7-4 決定 2）。元の画像を見ないまま生成すると、
  戻らない生成枠を使ってしまうこと
- 受け口の検証（他人の下書き・生成済み・別のお題・削除済み）は `GET /api/attempts/:id` の応答
  （404、または `status` / `post_id` の不一致）で判定できる。**バックエンドの変更は要らない**

### 決定 3：3-3（タイトル編集）は取り込まない

私の判断。ユーザーは反対しなかった（2026-10-20）。3-3 は 🔵 で背骨に入っておらず、Rails 側の作業
（バリデーション・`PATCH`・request spec）も要る。7-6a の「投稿したお題」タブは表示だけにする。

### 決定 4：開いているタブとページは URL に載せる

ユーザーの決定（2026-10-20）。

- 形：`/mypage?tab=<tab>&page=<n>`。`tab` は `posts` | `attempts` | `drafts` | `favorites`
- 既定値（`tab=posts`・`page=1`）は URL から省く（`/posts` と同じ規則）
- 不正な `tab` は `posts` に、不正な `page` は 1 に丸める。どんな入力でも例外を投げない
- **タブを切り替えたら 1 ページ目に戻す**（`page` を渡さない。別のタブの 3 ページ目は無関係な内容になるため）
- タブの値から API のパスを作る（`posts` → `/api/me/posts` など）。画面の URL と API のパスは
  **同じモジュールの関数から作る**（`posts-query.ts` と同じ理由）
- 純粋関数のモジュール `src/lib/mypage/mypage-query.ts` に置き、Vitest で検査する
  （`test/lib/mypage/mypage-query.test.ts`）。CLAUDE.md の「UI から切り出せる純粋なロジックには Vitest」に当たる
- ページは `/posts` と同じく、サーバーコンポーネントが `searchParams` prop を正規化してクライアントに渡す。
  `useSearchParams()` は使わない

理由：リロードや「戻る」で同じタブに戻れる。7-6b で下書きからお題詳細へ移って戻ったときも、下書きタブが
開いたままになる。

### 決定 5：「自分の挑戦」は専用のカードにする

ユーザーの決定（2026-10-20）。`AttemptCard` だと全部のカードに自分の名前が出て、どのお題への挑戦か
分からないため。

- 中身：再現画像（正方形）、描写文（3 行まで）、「お題：<タイトル>」、いいね数。自分の名前は出さない
- お題が生きている挑戦：カード全体を挑戦詳細へのリンクにする（`AttemptCard` と同じ）
- **お題が削除済みの挑戦：リンクにしない**（開くと必ず 404 になる）。お題名の代わりに
  「お題は削除されました」と出す。再現画像は出す（取り下げられたのはお題の画像で、再現画像は自分のもの。
  私の判断）
- 片付けるための削除ボタンは 7-6b で足す
- `AttemptCard` は変えない（お題詳細と表彰台で使っている）。新しい部品として作る

### 決定 6：下書きタブは一覧だけ出す

ユーザーの決定（2026-10-20）。4 タブの作りを 7-6a で揃え、7-6b の差分を操作だけにする。

- 中身：お題のサムネイル、お題のタイトル、描写文（3 行まで）
- **カードはリンクにしない**（私の判断）。お題詳細へリンクすると空の描写フォームが開き、保存した文面が
  消えたように見えるため。7-6b で「編集」などのボタンを足すときに、受け口と一緒に導線を作る
- お題が削除済みの下書き：サムネイルの位置に同じ寸法の空枠を出し、「お題は削除されました」と出す
- main をマージすると Vercel の本番に出る。7-6b までは「保存した下書きを確かめられる」だけの状態になる
  （ユーザーが了承済み）

### 決定 7：ヘッダーの入口は頭文字のアバター＋名前のリンク

ユーザーの決定（2026-10-20）。

- 今の名前の `<span>` を、頭文字の丸＋名前の `<Link href="/mypage">` に置き換える。「ログアウト」は
  今のまま横に置く
- 頭文字（**/code-review 後の変更、2026-10-21**）：名前の先頭から書記素（`Intl.Segmenter`。無い環境は
  コードポイントで代替）で見て、**見えない書記素だけを飛ばし**、最初の 1 つを取る。見えない書記素とは、
  含むコードポイントがすべて結合文字・書式文字（幅ゼロの空白など）・区切り（空白）・制御文字のもの
  （`/^[\p{M}\p{Cf}\p{Z}\p{Cc}]+$/u`）。記号（☆ ♪）・句読点・国旗・キーキャップは見えるので頭文字になる。
  大文字にして 1 書記素のままなら大文字にし（「ß」は「SS」になるのでそのまま）、見つからなければ `?`。
  **この規則は同日の 2 回目のレビュー後の「文字・数字・絵文字を含む書記素だけを取る」を置き換えた**。
  あの絞り込みは「☆☆☆」「♪」を `?` にし、国旗とキーキャップを飛ばして次の文字を取っていた。
  当初は `Array.from(name)[0]`（コードポイント）で、結合文字や ZWJ の絵文字の崩れは許容としていたが、
  挑戦カードの切り出しと同じ `charactersOf` を使えば割れないので改めた。丸は `overflow-hidden` で、
  結合文字が大量に重なった書記素がはみ出さないようにする
- 丸は `aria-hidden`。リンクの読み上げ名は名前だけにする
- 名前の切り詰め（`max-w-40 truncate`）と `title` は今の作りを引き継ぐ
- マイページのプロフィールヘッダーにも同じ丸を大きく出す。部品は 1 つにする

### 決定 8：統計はページで `GET /api/me` を取る

- マイページを開くたびに取り直す（`AuthProvider` には持たせない。`MeResponse` のコメントのとおり）
- 名前は `useAuth()` の値ですぐ出し、統計の 3 つだけ読み込み中の枠を出す
- 統計の取得に失敗しても、タブの一覧は止めない。統計の位置に短いエラー文と「再試行」を出す（私の判断）
- 表示：「投稿したお題 N」「挑戦 N」「獲得いいね N」

### 決定 9：一覧の取得と表示の状態は `PostList` に揃える

- `useEffect` ＋ `AbortController` ＋ `requestKey`（API パス＋再試行回数）の形。読み込み中はスケルトン、
  失敗は文言＋「再試行」
- 範囲外のページ（`?page=99`、件数はあるのに空）は「このページには何もありません」＋「1 ページ目へ」
- 件数の表示（「全 N 件」）とページ送り（`Pagination`）も `/posts` と同じ
- タブの切り替えは `SortToggle` と同じ見た目の `<Link>` の並びにする。WAI-ARIA の tablist にはしない
  （URL が変わるページ遷移なので、矢印キーで切り替わる tablist の約束と合わない。私の判断）。
  `<nav aria-label="マイページのタブ">`、選択中は `aria-current="page"`。
  `SortToggle` の `aria-label` と `aria-current` の値が違うので、そのままは使わない。同じ見た目の部品を作るか、
  `SortToggle` に `aria-label` と `aria-current` の値を渡せるようにするかは実装に任せる

### 決定 10：空状態

| タブ | 文言 | 行き先 |
|---|---|---|
| 投稿したお題 | まだお題を投稿していません | 「お題を投稿」→ `/posts/new` |
| 自分の挑戦 | まだ挑戦していません | 「お題を探す」→ `/posts` |
| 下書き | 保存した下書きはありません | 「お題を探す」→ `/posts` |
| お気に入り | お気に入りしたお題はありません | 「お題を探す」→ `/posts` |

文言は私の案。変えるときは画面のコード内の定数だけを変えればよい（バックの文言ではない）。

- `metadata.title` は「マイページ」

## 既知の制約

1. **生成中・失敗の挑戦はどのタブにも出ない。** 下書きから「画像を生成」を押すと、その下書きのレコードが
   `generating` に変わるので、下書きタブから消える。生成中に画面を離れた挑戦と、失敗した挑戦は、
   公開されるまで（失敗ならずっと）マイページから見えない。API の絞り込みを変える話なので 4-5 で扱う
   （backlog 4-5 に経緯がある）。7-6a ではバックエンドを変えない
2. **統計と一覧は別々のリクエストなので、ずれることがある。** 別のタブで投稿した直後などに、
   統計の件数と「全 N 件」が一瞬食い違う。どちらもリロードで揃う

## テスト

- **Vitest**：`mypage-query.ts`（タブと page の正規化、既定値を省いた URL、タブの切り替えで page が消えること、
  API パスとの対応、不正な値で例外を投げないこと）
- **RTL・コンポーネント単体テストは書かない**（CLAUDE.md「テスト戦略」）
- **E2E は 8-1**。この issue では追加しない
- **ブラウザでの確認**（`docker compose up`）：
  - 4 タブの中身・空状態・ページ送り・範囲外のページ
  - `/mypage?tab=drafts` を**直接ロード**したとき・リロードしたときに `/login` へ飛ばされないこと
    （`<Link>` での遷移だけではハイドレーションの経路を確かめられない）
  - 未ログインで `/mypage` を開くと `/login?next=/mypage` に送られること
  - `/mypage?tab=drafts` を開いたまま失効させ、ログインし直すと `/mypage?tab=drafts` に戻ること
    （`RequireAuth` がクエリごと戻り先にする）
  - 削除済みのお題に付いた挑戦・下書きの見え方（リンクにならないこと）
  - お題の画像に 16:9・3:4 などの縦横比を混ぜて、サムネイルの見え方を確かめる（開発データは 64px の正方形だけ）
  - 長い名前（空白なし）でヘッダーとプロフィールが崩れないこと、スマホ幅で横スクロールが出ないこと
  - 統計の取得だけを失敗させたとき、一覧が出続けること
