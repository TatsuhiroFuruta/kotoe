## 決定

### 決定 1：本番でのコアループの確認（手で行う）

本番の `https://kotoe.vercel.app` で、新しく作ったアカウントで次を 1 周する。

| # | 操作 | 見ること（つなぎ目） |
|---|---|---|
| 1 | `/api/health` を叩いて Render を起こす | `{"status":"ok","database":"ok"}`（Neon のプール接続） |
| 2 | 登録 → ログイン状態になる | Vercel↔Render の CORS、JWT の受け渡し |
| 3 | お題を投稿（画像＋タイトル） | Rails → Cloudinary（`kotoe/production/posts/`）へのアップロード、配信画像の表示 |
| 4 | お題の詳細で描写を書き「保存」 | 下書き（`draft`）の保存 |
| 5 | 「画像を生成」 | Solid Queue（Puma 内）→ OpenAI → Cloudinary。ポーリングで `published` になり即公開される |
| 6 | 比較ビュー | 元画像と生成画像が並ぶ |
| 7 | いいね | 認証付きのトグル |
| 8 | 再読み込み（直接ロード） | ログイン状態が保たれる（ハイドレーション経路） |
| 9 | ログアウト → 認証が要る画面を開く | 未認証のガード |

- 画像は**縦横比の違うもの**（16:9 か 3:4）を使う。開発データは正方形ばかりで、比率の崩れを見逃した前例がある
- 生成は 1 回だけ（約 $0.011）。アプリ側の 1 日上限（50 枚）・OpenAI の上限設定は `deployment.md` のとおり
- 結果（各手順の OK/NG、生成にかかった時間、気づいたこと）は **issue #30 のコメント**に残す
- **確認後、使ったお題・挑戦は画面（マイページ）から論理削除する。** アカウントも物理削除はしない（CLAUDE.md の discard の原則）。
  Cloudinary の画像は残る（3-3 の確認と同じ扱い）
- NG が出たら、この PR では直さない。原因を調べ、別の issue（または fix ブランチ）に切り出してから 8-2b に戻る
- ブラウザの操作は、ユーザーが行うか、Claude in Chrome で行うかを実装計画で決める（決定ではなく進め方の話）

### 決定 2：「E2E が green」の確かめ方

backlog の完了条件「E2E が green」は、**main の CI の `e2e (playwright)` ジョブが green であること**と読む（8-1 の決定）。
PR を出す時点の main の最新の実行を確認し、その run の URL を issue #30 の記録に添える。本番には流さない。

### 決定 3：カスタムドメインは 8-12 として切り出す

- 理由：MVP では限られた人に `kotoe.vercel.app` のまま使ってもらい、様子を見てから決めるため（ユーザーの判断、2026-11-15）
- **「公開前にやること」の一覧には入れない。** 限られた人に見せる段階では Vercel の URL で足りる
- ラベルは `本リリース`。依存は 8-2b
- 新しい issue に書いておくこと：
  - 独自ドメインを足しても **`kotoe.vercel.app` は使えるまま**（Vercel は両方を配信する）。先に使ってもらった人に URL を配り直す必要はない
  - Render の **`CORS_ALLOWED_ORIGINS` に新しいオリジンを足す**必要がある（完全一致のため）。足さないと、新しいドメインから開いた画面だけ API が全部 CORS で落ちる
  - 8-5（CSP）・8-3（OGP）・8-8（GA4）は URL・オリジンを含むので、どちらが先かで設定の書き直しが要る
  - 本番固有の統合なので、入れた回に最小の疎通確認を足す（CLAUDE.md）
- backlog の 8-2b のタスクからカスタムドメイン/DNS を外し、「8-12 へ切り出し」と書く
- `deployment.md` の「範囲外：カスタムドメイン/DNS（8-2b）」を 8-12 に直す。
  CLAUDE.md の「本番環境に依存する部分」の列挙はそのまま（どの issue で入れても当てはまる方針のため）

### 決定 4：疎通確認の残骸は残す

- 本番 DB の `smoke@kotoe.test`（8-2a）・`smoke-3-1@example.com`（3-1）は**消さずに残す**（ユーザーの判断、2026-11-15）。
  物理削除・論理削除のどちらもしない
- Cloudinary の `kotoe/production/posts/` に残る 1x1 PNG も残す（Claude の判断。どの画面にも出ず、
  アカウントと同じ扱いに揃えるため）
- `deployment.md` の「スモークユーザーの cleanup」の「**未処理**」を、「**残すことにした**（2026-11-15、8-2b）」に
  書き換える。今後の issue でこの作業が「やり残し」に見えないようにするため。削除の手順（`psql` の `DELETE`）は、
  後で消したくなったときのために残しておく
- 限られた人に使ってもらう中で、この 2 件が画面（一覧・ランキングなど）に出て紛らわしいと分かったら、そのときに見直す
- 決定 1 で使うアカウント・お題・挑戦は、決定 1 のとおり論理削除する
